# M4 loopback HTTP conformance

13 November 2026 · [Transport contract](contracts.md#mcp-transport-and-execution) · [ADR-002](../DECISIONS.md#adr-002--dual-revision-mcp-and-sdk-boundary)

The opt-in `server-http` feature exposes `mcp_transport::http::bind_loopback`. It takes the shared M3 runtime and a trusted local operator and binds `/mcp` on an ephemeral `127.0.0.1` port. The wire suite projects the schema 1 catalog into this runtime and uses a synthetic adapter for tool calls and resource reads. Its independent Hyper client opens a real socket for each POST and parses JSON and SSE without MCP SDK types. Both revisions exercise the same tool input and output schemas, policy decisions, resource and resource-template reads, and parameterized prompts. ## Observed wire behavior

| Case | Observed result |
| --- | --- |
| Modern direct requests | Discovery and lists return JSON. Tool calls and resource reads use request-scoped SSE. Independent connections supply their own version and client capabilities. Modern replies omit a session ID even when the request carries a legacy session or event ID. Discovery, lists and successful resource reads include the modern cache fields. |
| Modern rejection | Missing, duplicate or mismatched version, method and applicable name headers return HTTP 400 and `-32020`. The Base64 name sentinel is decoded before comparison. An unsupported modern revision returns HTTP 400 and `-32022` with supported revisions. Missing or malformed required metadata returns HTTP 400 and `-32602`. An unknown method returns HTTP 404 and `-32601`. Refused requests make zero adapter preparations. |
| HTTP checks and limits | The listener accepts its exact numeric Host and same-origin Origin or a missing Origin. Invalid values return 403 even when forwarding headers name the listener. GET is 405, and modern-only DELETE is 405. Invalid Content-Type and Accept produce 415 and 406. A 1 MiB POST succeeds and a chunked POST one byte larger returns 413 before adapter preparation. An oversized serialized SSE event is replaced with a bounded `-32603` carrying the original request ID. |
| Modern disconnect | The response body opens before a slow tool returns any MCP message. Closing it stops the associated adapter within the one-second test window with or without a progress token. A separate client with the same JSON-RPC ID remains active through the disconnect and completes after release. |
| Legacy issued sessions | Initialize negotiates `2025-11-25` and issues an in-memory session. The initialized and cancellation notifications return empty 202 replies. Subsequent legacy requests require the selected version and issued ID. Missing IDs return 400. Expired, deleted and pre-restart IDs return 404. A new initialize succeeds. The 129th session request returns 503 and a DELETE frees capacity while modern calls continue. |
| Legacy cancellation and sessionless SDK comparison | In an issued session, closing SSE leaves the adapter active. An explicit cancellation POST stops the named call within the one-second test window, and the client receives no further event on that stream. A sibling ID in the same session remains active and completes after release. In the sessionless comparison, closing SSE stops the adapter. The SDK acknowledges a cancellation POST with 202, but the call remains active until its deadline when the response stream stays open. |
| Runtime errors and diagnostics | Invalid arguments and policy denials report namespaced diagnostics with correlation IDs and zero execution. Invalid adapter output reports a tool error. A missing resource reports `-32602` in modern and `-32002` in legacy. A missing prompt or invalid list cursor reports `-32602`. An SDK trace canary stays out of the filtered diagnostic sink. |
| Isolated SDK capabilities and output | A standalone SDK test handler requires client elicitation and returns HTTP 400 and `-32021` with the required capability when the request omits it. With the capability declared, the handler returns array and integer structured results and text equivalents. The portable catalog uses object-shaped tool schemas and results across both revisions. |

The listener uses a 10-second body-read timeout, 1 MiB per request and serialized response or SSE event, and 1 KiB per string request ID or progress token. The dual-revision profile caps legacy sessions at 128 with a default 15-minute idle expiry. The expiry test uses a 300 ms configuration. The listener offers no standalone SSE or event replay. Hosts apply `mcp_transport::sdk_diagnostic_filter` to each tracing sink before serving. ## SDK selection

Keep exact `rmcp = "=3.9.0"` for M3 and M4. The SDK's negotiated HTTP service waits for the first handler message before sending headers, including when configured for SSE. The no-progress test exposed that behavior before the boundary change. The loopback listener validates and normalizes the request before opening SSE. It writes an SSE comment and drives the same SDK handler with `OneshotTransport` and `serve_directly_with_ct`. The body owns the running service and drops it on disconnect. Fast modern replies and legacy session handling continue through the SDK HTTP service. The request-scoped path supports the fixed catalog and its existing capabilities. [Pinned SDK release](https://github.com/modelcontextprotocol/rust-sdk/releases/tag/rmcp-v3.9.0) · [SDK negotiated response path](https://github.com/modelcontextprotocol/rust-sdk/blob/rmcp-v3.9.0/crates/rmcp/src/transport/streamable_http_server/tower.rs#L1667-L1730)

The separate `server-http,client-http-rustls` test runs the SDK's Auto lifecycle with a five-second case limit and proxies and redirects disabled. Against the modern-only listener, a future-version probe retries at `2026-07-28` and completes a real list and SSE tool call. A probe with no shared version reports the supported version. A raw loopback peer confirms the client sends `initialize` and `notifications/initialized` after an empty or unrecognized HTTP 400. Recognized `-32020` and `-32021` preserve the modern errors and the peer receives no initialize. M7 verifies the selected legacy version before using peer capabilities.
