# Managed local playground

The desktop and CLI start the first-party builder CLI as a supervised stdio worker. The application service reads the saved schema 1 manifest, builds an inert review and checks the current revision again on admission. A review binds the project's registration and exact manifest bytes, approved grants and prompts, mode and scenario, native file-root identities, credential sources and policy limits. The native review also binds the local operator, resolved executable and working directory identities, executable bytes, arguments and environment. The installed worker comes from the desktop executable's directory. The CLI uses its own absolute executable path.

- **Windows x64** uses a kill-on-close Job Object on local NTFS. The worker starts as a native console PE with an explicit stdio handle list. The held image handle denies concurrent write and delete access, including through another NTFS hard link to the same image. Any other launcher in the same host must use an explicit handle list so its child cannot inherit preview pipes. [Windows file sharing](https://learn.microsoft.com/en-us/windows/desktop/FileIO/creating-and-opening-files) · [NTFS hard links](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)
- **Linux x64** executes the reviewed ELF descriptor using the kernel's descriptor-based exec on the supported Ubuntu 24.04 profile. It uses the held working-directory descriptor and closes unrelated descriptors across exec.
- **macOS Apple silicon** uses a suspended POSIX spawn of the original Mach-O artifact. It checks the loaded image path before resuming and uses the held working-directory descriptor. The original installed artifact remains subject to macOS signature and Gatekeeper checks. The physical launch route must belong to the operator or root. An inherited ACL that grants mutation is refused. The built-in administrator group's access to the system Applications directory is trusted like other local administrator access.

Linux and macOS use a private Unix process group and explicit stdio descriptors. The first-party worker and its loaded libraries run with the operator's OS privileges. Use a trusted installation and working directory. Normal shutdown and dropping the owning session signal the worker and its inherited group, and reap the direct worker. After abrupt host termination, the first-party worker observes EOF on its private input. Unix process groups do not contain processes that detach from them, and abrupt host termination does not provide a kernel kill-on-close job for descendants.

## Replay a saved fixture

Run these commands from PowerShell against a folder containing the catalog sample saved as `mcp-project.json`. The selection of grants and prompts defaults to empty. Use the same selections for review and replay.

```powershell
mcp-builder playground review 'C:\work\catalog' --scenario known_item --grant catalog_read
mcp-builder --json playground replay 'C:\work\catalog' --scenario known_item --grant catalog_read --approve 'sha256:<digest-from-review>'
```

Use `--protocol modern` for MCP `2026-07-28` or `--protocol legacy` for `2025-11-25`. Auto is the default. `--timeout-ms` bounds the call and accepts 1 through 30,000 ms. JSON output includes a versioned terminal run record and a bounded trace with metadata. A failed replay puts the run ID, run record and trace in `error.details`. Use `--trace-payloads` with `--json` to explicitly export the current sanitized trace. An assertion mismatch returns exit 4 and the affected assertion index and visible path. Omitted or stale approval returns exit 3. A matching saved error assertion is a passing run. A missing fixture returns exit 5 with `fixture.missing`.

Each CLI replay explicitly supplies the current digest for that operation. In the application service the prepared review expires after five minutes. Approval and start consume their respective objects, including on failure. Prepare a fresh review after an edit or a change to approved targets. Fixture replay performs no DNS, upstream connections, file-root access or credential lookup. Named REST origins use a fixed synthetic public peer. Explicit peer ranges can deny that peer. IP literals and localhost use the corresponding address in the shared policy check.

## Use the application service

`ProjectService::prepare_playground` takes the selected registration or project folder, a trusted first-party worker path, mode and approved access. Present the returned review before calling `approve`. `ApprovedProjectPreview::start` checks the saved revision and starts the supervised session. The managed connection offers discovery, scenario replay, live invocation, a trace snapshot and stop. Saved live replay is limited to read-only calls. Writes require an explicit live invocation. For a live session, configure concrete roots and choose session-only or explicitly named environment credential sources. Approved REST credentials are scoped to the project, local principal, capability, binding, reference and original upstream. Credential values travel over the private pipe handoff. The handoff runs before MCP initialization and carries the approved manifest snapshot. Linux and macOS start with an empty worker environment. On Windows the only entry is the `SystemRoot` path queried from the OS and included in the launch review. [Windows system directory](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemwindowsdirectoryw)

The client accepts only the two supported revisions, bounds stdio frames and propagates cancellation at request scope. Start an installed worker in the same runtime that will manage its asynchronous pipes. Explicit stop closes stdin and gives the worker up to two seconds to exit. It then signals the remaining worker processes and uses a five-second shutdown budget. Dropping the session enforces the platform-specific process ownership described above. Close a session before switching projects or policy selections.

Trace capture is in memory and defaults to metadata. The ring bounds entry count and serialized bytes, records loss and truncation, and discards transient payloads on close. The CLI snapshots the requested trace before stopping. Peer error text and raw stderr stay outside the trace. Display payloads and opt-in evidence use credential and scenario-path redaction. Assertion checks run on the bounded normalized result before redaction. Live writes conservatively report an unknown effect where the starter runtime cannot confirm an upstream commit.

The desktop uses purpose-bound folder selections and one-use reviews and approvals. The installers place the first-party worker alongside the desktop. Live file mappings and credential sources belong to a single review. The CLI can script single or full-suite fixture replay. Both hosts apply `sdk_diagnostic_filter` to their diagnostic layers. The CLI enters worker mode before initializing its own subscriber. Per-profile run history and export reports follow the evidence-store work in the plan. ## Verification

Windows 11 Pro x64, build 26200, with Rust 1.99.1 and the locked dependencies passed 130 headless workspace tests and six stdio wire cases. The 35 M7 tests cover explicit and automatic revision selection, refusal of `2025-03-26`, native job admission and teardown, the private handoff, policy-bound synthetic fixtures, redacted traces, and the CLI's pass, mismatch, invalid-argument and missing-fixture results. A malformed JSON-RPC frame in the controlled worker received a parse error and a later fixture call succeeded. A reviewed live loopback call timed out and closed its socket, and the same stdio session completed the next request. A native file-root replacement after approval was refused, and the original root succeeded after a new review.

The primary checkout passed the headless suite, Clippy, formatting and the CLI smoke after integration. Separate runs passed the stdio client and server cases, the loopback HTTP suite and all six SDK feature profiles. A fresh Windows export built and passed its 23 standalone tests. Inspector 2.15.0 negotiated both revisions and listed the approved prompt from that export. Hosted foundation checks cover the Unix launch review, private descriptors, process-group shutdown, and both stdio revisions through CLI fixtures.
