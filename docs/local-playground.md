# Managed local playground

The Windows pilot starts the installed builder CLI as a supervised stdio worker. The application service reads the saved schema 1 manifest, builds an inert review and checks the current revision again on admission. A review binds the project's registration and exact manifest bytes, the approved grants and prompts, the selected mode and scenario, native file-root identities, credential sources and policy limits. Native review binds the Windows operator SID, resolved executable and working directory identities, executable bytes, the argument vector and the environment.

Windows starts the reviewed console PE image on local NTFS in a kill-on-close Job Object with an explicit three-handle stdio list. The install directory supplies the working directory. The worker runs under the operator's account and shares the trust of the installed binary and its libraries. Its Job Object contains normal job members and limits their lifetime. Any other launcher in the same host must use an explicit handle list so its child cannot inherit a preview pipe. Cargo-built CLI binaries can have another NTFS name for the same image. The held image handle denies concurrent write and delete access, including through that second name. The worker uses the same runtime, policy and starter adapters as a standalone export. The current supervisor returns `playground.launch_unsupported` on Linux and macOS. [Windows file sharing](https://learn.microsoft.com/en-us/windows/desktop/FileIO/creating-and-opening-files) · [NTFS hard links](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)

## Replay a saved fixture

Run these commands from PowerShell against a folder containing the catalog sample saved as `mcp-project.json`. The selection of grants and prompts defaults to empty. Use the same selections for review and replay.

```powershell
mcp-builder playground review 'C:\work\catalog' --scenario known_item --grant catalog_read
mcp-builder --json playground replay 'C:\work\catalog' --scenario known_item --grant catalog_read --approve 'sha256:<digest-from-review>'
```

Use `--protocol modern` for MCP `2026-07-28` or `--protocol legacy` for `2025-11-25`. Auto is the default. `--timeout-ms` bounds the call and accepts 1 through 30,000 ms. JSON output includes a versioned terminal run record and a bounded trace with metadata. A failed replay puts the run ID, run record and trace in `error.details`. Use `--trace-payloads` with `--json` to explicitly export the current sanitized trace. An assertion mismatch returns exit 4 and the affected assertion index and visible path. Omitted or stale approval returns exit 3. A matching saved error assertion is a passing run. A missing fixture returns exit 5 with `fixture.missing`.

Each CLI replay explicitly supplies the current digest for that operation. In the application service the prepared review expires after five minutes. Approval and start consume their respective objects, including on failure. Prepare a fresh review after an edit or a change to approved targets. Fixture replay performs no DNS, upstream connections, file-root access or credential lookup. Named REST origins use a fixed synthetic public peer. Explicit peer ranges can deny that peer. IP literals and localhost use the corresponding address in the shared policy check.

## Use the application service

`ProjectService::prepare_playground` takes the selected registration or project folder, a trusted first-party worker path, mode and approved access. Present the returned review before calling `approve`. `ApprovedProjectPreview::start` checks the saved revision and starts the supervised session. The managed connection offers discovery, scenario replay, live invocation, a trace snapshot and stop. Saved live replay is limited to read-only calls. Writes require an explicit live invocation. For a live session, configure concrete roots and choose session-only or explicitly named environment credential sources. Approved REST credentials are scoped to the project, local principal, capability, binding, reference and original upstream. Credential values travel over the private pipe handoff. The handoff runs before MCP initialization and carries the approved manifest snapshot. The worker's only environment entry is the `SystemRoot` path queried from Windows and included in the launch review. [Windows system directory](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemwindowsdirectoryw)

The client accepts only the two supported revisions, bounds stdio frames and propagates cancellation at request scope. Start an installed worker in the same runtime that will manage its asynchronous pipes. Explicit stop closes stdin and gives the worker up to two seconds to exit. It then terminates and checks the job within the five-second shutdown budget. Dropping the session closes the job. Close a session before switching projects or policy selections.

Trace capture is in memory and defaults to metadata. The ring bounds entry count and serialized bytes, records loss and truncation, and discards transient payloads on close. The CLI snapshots the requested trace before stopping. Peer error text and raw stderr stay outside the trace. Display payloads and opt-in evidence use credential and scenario-path redaction. Assertion checks run on the bounded normalized result before redaction. Live writes conservatively report an unknown effect where the starter runtime cannot confirm an upstream commit.

The desktop uses purpose-bound folder selections and one-use reviews and approvals. The pilot installer places the first-party worker alongside the desktop. Live file mappings and credential sources belong to a single review. The CLI can script single or full-suite fixture replay. Both hosts apply `sdk_diagnostic_filter` to their diagnostic layers. The CLI enters worker mode before initializing its own subscriber. Per-profile run history and export reports follow the evidence-store work in the plan. ## Verification

Windows 11 Pro x64, build 26200, with Rust 1.99.1 and the locked dependencies passed 130 headless workspace tests and six stdio wire cases. The 35 M7 tests cover explicit and automatic revision selection, refusal of `2025-03-26`, native job admission and teardown, the private handoff, policy-bound synthetic fixtures, redacted traces, and the CLI's pass, mismatch, invalid-argument and missing-fixture results. A malformed JSON-RPC frame in the controlled worker received a parse error and a later fixture call succeeded. A reviewed live loopback call timed out and closed its socket, and the same stdio session completed the next request. A native file-root replacement after approval was refused, and the original root succeeded after a new review.

The primary checkout passed the headless suite, Clippy, formatting and the CLI smoke after integration. Separate runs passed the stdio client and server cases, the loopback HTTP suite and all six SDK feature profiles. A fresh Windows export built and passed its 23 standalone tests. Inspector 2.15.0 negotiated both revisions and listed the approved prompt from that export. The desktop crate passed its Windows compile check. Hosted CI and installed desktop launch evidence remain pending.
