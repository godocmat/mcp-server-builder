# MCP compatibility

Phase 0 · D1 · Sources checked 12 November 2026

Use **2026-07-28** as the primary target and **2025-11-25** as the compatibility floor. Both are published stable revisions. The local MVP ships stdio and uses loopback Streamable HTTP for conformance. Commercial v1 adds authenticated Streamable HTTP. Documentation and tagged source establish the starting matrix. The listed builds are candidates for wire verification. [Product plan](../PLAN.md), [2026-07-28 release](https://github.com/modelcontextprotocol/modelcontextprotocol/releases/tag/2026-07-28), [2025-11-25 release](https://github.com/modelcontextprotocol/modelcontextprotocol/releases/tag/2025-11-25), [2026-07-28 changes](https://modelcontextprotocol.io/specification/2026-07-28/changelog)

## Transport lifecycles

### 2026-07-28

- **Both transports.** Requests are self-contained. Put `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities` in `params._meta` on each request, including discovery. Send `io.modelcontextprotocol/clientInfo` and return `io.modelcontextprotocol/serverInfo` in result metadata as recommended. The server implements `server/discover`, which reports supported versions, capabilities, identity, and optional instructions. A client can call it first or invoke a method directly. The server serves modern requests without `initialize` or `notifications/initialized`. [Base protocol](https://modelcontextprotocol.io/specification/2026-07-28/basic), [Versioning and compatibility](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning), [Discovery](https://modelcontextprotocol.io/specification/2026-07-28/server/discover)
- **stdio.** Launch a subprocess and exchange UTF-8 JSON-RPC, one message per line. Reserve stdout for protocol messages and use stderr for process logs. Correlate responses by request ID on the shared channel. A dual-era client probes with `server/discover`. A recognized modern error keeps it on the modern path. Another error or probe timeout triggers `initialize`. EOF on stdin is the normal shutdown signal. Reap the process and apply an OS-appropriate bounded shutdown if needed. A restarted process needs fresh subscriptions. [stdio binding](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)
- **Streamable HTTP.** Send one JSON-RPC message per POST to one endpoint such as `/mcp`, with `Accept` covering `application/json` and `text/event-stream`. Clients accept either a single JSON reply or a Server-Sent Events (SSE) response stream carrying request-scoped notifications and the final reply. Modern requests use `MCP-Protocol-Version` and `Mcp-Method`. `tools/call`, `resources/read`, and `prompts/get` also require `Mcp-Name`. Compare the mirrored headers with the body before dispatch. Validate `Origin` and return HTTP 403 for an invalid origin. Bind the MVP fixture to loopback. Modern traffic carries no MCP session ID and uses POST response streams for subscriptions. The modern-only endpoint should return 405 for GET and DELETE. A broken stream has no replay cursor. Any retry uses a new request ID and follows the operation's retry policy. [Streamable HTTP binding](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)
- **HTTP fallback.** A dual-era client can try a modern request first. On HTTP 400, inspect the body. A recognized modern error calls for a version retry or a request correction. An empty or unrecognized error body on the probe permits legacy `initialize` fallback. Use a non-mutating probe and handle an OAuth challenge as authentication. [HTTP backward compatibility](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http#backward-compatibility)

### 2025-11-25

- **Both transports.** The client sends `initialize` with its version, capabilities, and identity. The server echoes a supported version proposal or returns another supported legacy version, with its capabilities, identity, and optional instructions. The client sends `notifications/initialized` before normal operations and should disconnect if it cannot speak the selected version. Use the capabilities negotiated for that connection. Answer legacy `ping` and use the transport to shut down. [Legacy lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [Legacy ping](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/ping)
- **stdio.** The handshake belongs to the subprocess connection. Use the same newline-delimited framing and stdout discipline as modern stdio. Close stdin, wait, and reap the child. An opening `initialize` selects the legacy lifecycle on a dual-era server. [Legacy stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio), [Dual-era server behavior](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning#backward-compatibility-with-initialization-based-versions)
- **Streamable HTTP.** Send the negotiated `MCP-Protocol-Version` after initialization. The server may issue `Mcp-Session-Id` with the initialize result. If issued, send it on every subsequent HTTP request. A server that requires it should return 400 when it is missing and must return 404 after that session ends. On a session 404, initialize again without the old ID. A client should try DELETE when done with an issued session. The server may return 405. A standalone GET SSE stream is optional. Optional resumption uses GET with `Last-Event-ID` and resumes only the original stream. Accepted client notifications or replies return HTTP 202 with an empty body. POST requests can receive JSON or SSE replies. [Legacy Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#streamable-http)

The legacy path above still uses **Streamable HTTP**. The separate **2024-11-05 HTTP+SSE** transport is deferred by the plan. Keep the legacy headerless fallback to 2025-03-26 outside the supported-version matrix. Verify how the SDK treats headerless legacy traffic before adopting a production profile. [Legacy version header](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#protocol-version-header), [Modern transport compatibility](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http#backward-compatibility)

## Errors, timeouts, and cancellation

- **JSON-RPC and tool errors.** Echo the request ID when readable. Parse errors, invalid requests, unknown methods, malformed parameters, and internal failures use JSON-RPC errors. For a valid `tools/call` to a known tool, argument schema failures, business errors, and upstream failures use an actionable tool result with `isError: true`. An unknown tool or malformed `tools/call` envelope uses a protocol error such as `-32602`. A tool result can carry both `resultType: "complete"` and `isError: true` on modern clients. Map permission denials after HTTP authorization to a sanitized error appropriate to the capability. [JSON-RPC messages and codes](https://modelcontextprotocol.io/specification/2026-07-28/basic#error-codes), [Modern tool errors](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#error-handling), [Legacy tool errors](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#error-handling)
- **Resource and prompt errors.** A missing resource returns `-32602` on 2026-07-28 and `-32002` on 2025-11-25. A modern client should recognize the legacy code for compatibility. Unknown prompt names and missing required prompt arguments use `-32602` in both revisions. [Modern resource errors](https://modelcontextprotocol.io/specification/2026-07-28/server/resources#error-handling), [Legacy resource errors](https://modelcontextprotocol.io/specification/2025-11-25/server/resources#error-handling), [Modern prompt errors](https://modelcontextprotocol.io/specification/2026-07-28/server/prompts#error-handling), [Legacy prompt errors](https://modelcontextprotocol.io/specification/2025-11-25/server/prompts#error-handling)
- **Modern HTTP errors.** Required header missing, malformed, or inconsistent with the body yields HTTP 400 with `HeaderMismatch` (`-32020`). An unsupported version yields `UnsupportedProtocolVersionError` (`-32022`) and the supported revisions. This is HTTP 400 on HTTP and a JSON-RPC error on stdio. Missing a capability the method requires yields `MissingRequiredClientCapability` (`-32021`, HTTP 400 on HTTP). An unknown RPC method yields HTTP 404 with `-32601`, distinct from a legacy expired session. An invalid or unsupported legacy HTTP version header yields HTTP 400. [Modern error codes](https://modelcontextprotocol.io/specification/2026-07-28/basic#error-codes), [HTTP version and header validation](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http#request-metadata), [Legacy version header](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#protocol-version-header)

| Revision | stdio | Streamable HTTP |
| --- | --- | --- |
| 2026-07-28 | Send `notifications/cancelled` with the in-flight request ID. Keep the subprocess and unrelated requests running. | Close that request's SSE response stream. The server treats the close as cancellation, stops work as soon as practical, and stops sending messages for that request. Use an SSE fixture to prove teardown. [Modern cancellation](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation) |
| 2025-11-25 | Send `notifications/cancelled` for an in-flight request other than `initialize`. | POST the same notification on the negotiated legacy connection. A disconnected response stream by itself should leave the request running subject to its deadline. [Legacy cancellation](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation), [Legacy HTTP POST and disconnection](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#sending-messages-to-the-server) |

Give every request a deadline and a hard maximum even while progress arrives. Propagate cancellation into adapter execution, release resources, ignore late results on the client, and handle unknown IDs and completion races. Record whether work completed before cancellation. A disconnected client cannot infer whether a side effect already committed. Retry a side-effecting call only with an explicit safe retry or idempotency contract. [Modern timeouts and cancellation races](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation#timeouts), [Legacy timeouts](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle#timeouts)

## HTTP authorization

Treat the deployed MCP endpoint as an OAuth resource server backed by the external authorization server selected in D3/D5. For v1, serve protected-resource metadata with the canonical MCP URL in `resource` and the issuer in `authorization_servers`. Include `resource_metadata` in the HTTP 401 `WWW-Authenticate` challenge and publish the RFC 9728 well-known metadata path. The playground client tests both paths, discovers RFC 8414 or OIDC metadata, uses authorization code with PKCE S256, and sends the canonical `resource` in authorization and token requests. The modern flow validates the discovery issuer and validates `iss` on callbacks according to RFC 9207. A present `iss` must match, and a missing `iss` fails if the provider advertised it. [Modern authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [Modern discovery](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/authorization-server-discovery), [Legacy authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

Use bearer tokens on each protected HTTP request, including requests associated with a legacy session. Verify token validity, issuer, resource or audience, expiry, and scopes before dispatch. Bind any legacy session to the authenticated caller. Expect 401 for missing or invalid tokens and 403 for insufficient scope, with a scope challenge where applicable. Test refresh and reauthorization using the chosen provider. For local stdio, use OS process identity and launch trust, with environment or credential-store injection for integration credentials. [Modern token and scope handling](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization#access-token-usage), [Legacy authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

Clients that support all registration modes prefer configured pre-registration, then Client ID Metadata Documents (CIMD), then Dynamic Client Registration (DCR). The 2026-07-28 spec deprecates DCR and permits it for compatibility. Choose a provider with a public PKCE client path and record the exact registration flow and loopback redirect rules per client. Verify CIMD and pre-registration where documented. Exercise DCR if the provider or a selected legacy client requires it. [Modern registration](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration), [Legacy registration](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#client-registration-approaches)
